HTTPS certificate trust:

By default, iPXE trusts the same certificate authorities most operating systems do. If your PXE/HTTPS server uses a private certificate authority or a self-signed certificate (common with FOG-style deployments), you can build iPXE to trust it specifically.

Please note: The selected output format does not support HTTPS -- this is an iPXE decision for BIOS-format builds. Adding a certificate trust with this output will not function as intended. Please choose a UEFI output format to use this option.

What's the difference between trusting a CA and pinning a certificate? Trusting a certificate authority (CA) means iPXE will trust any server certificate signed by it -- the same way a browser trusts a public CA. That's different from pinning a single server's own certificate, which would need re-uploading every time that certificate is renewed. Trusting a stable private CA instead means your HTTPS server's certificate can be renewed without rebuilding every iPXE client, as long as the replacement is signed by the same CA.

Does this disable HTTPS security checks? No. Adding a trusted certificate does not disable iPXE's normal HTTPS checks. Your server's certificate must still match the exact hostname or IP address iPXE connects to, and be within its valid date range -- this only adds a new trusted root, it doesn't bypass anything.
